# Product Spec

採用日：2026-09-12

この文書は、今後の実装が満たすプロダクト仕様を定義する。実装済み機能の一覧ではない。ドメイン上の表現と制約は [Domain Model](DOMAIN_MODEL.md) に定義する。

旧 [Implementation Plan](IMPLEMENTATION_PLAN.md) は初期のポモドーロ実装に関する記録であり、今後の仕様としては本書とDomain Modelを優先する。

## 1. Product Goal

このアプリは、次の行動を支援する。

- 作業を始めやすくする。
- 作業中に何をするべきかを明確にする。
- 脱線を自覚したときに作業へ戻りやすくする。
- どの程度作業し、脱線から復帰できたかを後から把握できるようにする。

Pomodoroは、この目的のために作業時間を区切る一機能とする。一般的なTodo管理アプリにはしない。

## 2. MVP Scope

MVPは既存のTUIで機能とデータモデルを検証する。

| 対象 | 範囲 |
| --- | --- |
| 通常Focus | 設定時間での作業、開始・一時停止・再開・中止・リセット・スキップ |
| Current Task | 作業開始前の任意の一行入力、作業・中断中の表示、Sessionへの保存 |
| Quick Start | 固定2分の着手モード、終了または通常Focusへの継続 |
| Pause / Resume | 意図的な中断と再開 |
| Distraction / Return | 手動の脱線申告と復帰、申告から復帰までの時間記録 |
| Break | 短休憩・長休憩、手動開始 |
| History | Sessionと分析に必要な状態遷移の保存 |
| 永続化 | snapshotによる現在状態の復元、保存形式のバージョン管理、移行、元データの保護 |

MVPで全統計を表示する必要はない。後から計算できるだけのSession・event情報を失わず保存することを優先する。

次はMVPに含めない。

- Later Box：作業中の思いつきを一行だけ退避するInbox。将来候補とするが、ノート・Todo管理へ拡張する前提は置かない。
- AIによるタスク分解などの支援。
- Linux GUIへの移行。
- タスクの階層、プロジェクト、優先順位、期限による管理。

Linux GUIは将来の可能性として扱う。特定のGUI技術やWeb展開の順序は、本仕様の採用事項に含めない。

## 3. 用語と時間の意味

| 用語 | 定義 |
| --- | --- |
| Session | 一度開始した作業または休憩の試行。開始待ちの予定とは区別する |
| 計時済み時間 | 信頼できる実行区間でタイマーを進めた時間 |
| 記録上の作業時間 | FocusとQuick Startの計時済み時間の合計 |
| Pause | ユーザーが意図的に作業・休憩を中断すること |
| Distraction | ユーザーが脱線を自覚し、手動で申告すること |
| Return | Distractionの状態から作業へ戻る明示的な操作 |
| Recovery Time | Distraction申告からReturnまでの経過時間 |
| Observation Gap | 連続した計時として扱えない観測空白。Distraction申告とは区別する |

記録上の作業時間は、実際に集中していたことを保証する指標ではない。申告前の脱線は観測できず、実際の脱線開始時刻を推定して遡及補正しない。

Pause中、Distraction申告後、Break中、開始待ち、Quick Startの継続選択待ちは作業時間に含めない。中止・Reset・SkipしたSessionでも、すでに記録した作業時間は残す。

## 4. Current Task

- Focus・Quick Startとも、開始前に任意で一行のテキストを入力できる。
- 1 Sessionにつき1つとする。未入力でも開始できる。
- 空白だけの入力は未入力として扱う。
- 開始時の内容をSessionに保存し、MVPでは開始後に変更しない。
- 作業中・Pause中・Distraction中に確認できるようにする。
- Quick StartからFocusへ継続するときは内容を引き継ぐ。
- BreakにはCurrent Taskを持たせない。
- 独立したタスク一覧、Task ID、完了状態、階層、プロジェクト、優先順位、期限は持たせない。

## 5. Focus・Quick Start・Break

### 5.1 FocusとPomodoroの基本設定

| 設定 | 初期値 |
| --- | ---: |
| Focus | 25分 |
| 短休憩 | 5分 |
| 長休憩 | 15分 |
| 長休憩までのFocus自然完了数 | 4回 |

既存の作業・休憩時間と長休憩までの回数の設定を維持する。各Sessionの時間は開始時に確定する。

Focusの自然完了で、Pomodoroのラウンド進捗を1増やす。指定回数に達すると長休憩、それ以外は短休憩を用意する。次のSessionは自動開始しない。

長休憩を終えてFocus開始待ちへ進むと、ラウンド進捗を0に戻す。長休憩のResetは同じ休憩をやり直す操作なので、進捗を維持する。

設定変更は開始待ちでのみ許可する。設定適用時には既存仕様どおりラウンド進捗を0に戻し、開始待ちの種別は維持する。履歴上のFocus完了数は消さない。

### 5.2 Quick Start

- 着手の心理的負担を下げる、固定2分のモードとする。
- 通常Focusとは別のSessionKind・別のSessionとして扱う。
- Pause / ResumeとDistraction / Returnを利用できる。
- 自然完了後は計時を止め、「終了」または「通常Focusへ継続」の選択を待つ。
- 選択待ちの時間は作業時間に含めない。
- 「終了」でFocus開始待ちへ戻る。休憩を自動では挟まない。
- 「継続」で新しいFocusを開始する。設定されたFocus時間の全時間を与え、Quick Startの2分を加算・控除しない。
- Current Taskを引き継ぎ、継続元・継続先の関係を記録する。
- Quick Startの開始・完了・継続は、通常のPomodoro完了回数やラウンド進捗に加算しない。
- アプリを終了・再起動しても継続選択待ちを保持し、終了を選んだものとはみなさない。

### 5.3 Break

- 短休憩・長休憩の仕組みを維持し、開始は手動とする。
- Pause / Resumeを利用できる。Distraction / Returnは利用しない。
- Breakは作業時間に含めない。
- Focus・Quick Startと同様、正常終了中とObservation Gapでは計時を進めない。
- 復元・空白検出後に自動再開しない。

## 6. 中断・復帰・Session終了

### 6.1 PauseとDistraction

同時に開ける中断は1件だけとする。

- 実行中からPauseまたはDistractionへ移り、タイマーを止める。
- PauseはResumeで閉じ、残り時間から再開する。
- DistractionはReturnで閉じ、残り時間から再開する。
- 中断中に別種の中断を重ねたり、切り替えたりしない。
- Distraction申告後に中止した場合は、申告は記録するがReturn済みとは扱わない。
- Returnされなかった中断のRecovery Timeを0秒として扱わない。

Recovery Timeは、実際の脱線開始からの時間ではなく、申告からReturnまでの時間とする。Distraction中にアプリを終了しても、Returnまでの経過時間に終了中の時間を含める。ただし、その時間を作業時間に加算しない。

時計異常などにより時間を確定できない場合は、Returnの事実を残し、時間は不明として扱う。

### 6.2 終了結果

| 結果 | 意味 |
| --- | --- |
| Completed | 設定時間を計時し終えた |
| Cancelled | 今回の試行を中止した |
| Reset | 今回の試行を終了し、同じ種別・Current Taskで開始待ちに戻した |
| Skipped | 今回の試行を終了し、次の予定へ進んだ |

Reset後に開始したSessionは新しい試行とする。途中までの履歴を消したり、同じSessionを再利用したりしない。

FocusのSkipは休憩開始待ちへ進む。Quick Start・BreakのSkipはFocus開始待ちへ進む。開始前のSkipでは、実行していないSessionの履歴を作らない。

アプリ終了、Pause、DistractionはSession自体の終了結果にはしない。

## 7. 終了・再起動・Observation Gap

### 7.1 正常終了と復元

- 実行中の正常終了では、確認できた経過までを計時し、終了操作による中断として保存する。
- Pause中・Distraction中の終了では、元の中断理由を維持する。
- 新形式のsnapshotから、現在のSession・残り時間・中断理由・ラウンド進捗・継続選択待ちを復元する。
- 再起動だけでSessionを再開・完了させない。
- DistractionからはReturn、それ以外の中断からはResumeで再開する。

### 7.2 Observation Gapの内部ポリシー

Observation Gapの判定は、MVPでは内部ポリシーとして扱う。ユーザー向けの閾値設定は設けず、本仕様で具体的な閾値やチェックポイント間隔を固定しない。

- 明らかな長時間の観測空白は計時に含めない。
- 不明区間について、作業実績を推測して補完しない。
- 実行中の空白は、最後に信頼できる確認を行った時点で計時を止める。
- 保存状態がRunningのまま再起動した場合は、保存済みの最終確認時点から先を不明区間として扱う。
- 空白の判定を自然完了判定より先に行い、保存済みの期限超過だけで完了させない。
- すでに中断中なら新たな中断を重ねず、空白の事実を記録する。
- Observation GapをDistractionとして数えない。
- 開始待ち・継続選択待ちでは、空白を理由に新しいSessionや中断を作らない。

内部ポリシーは、同一プロセス内の観測の連続性を判断する。正常終了中の停止や、再起動時の不明区間を加算しない規則を閾値によって緩めない。

## 8. Historyと永続化

### 8.1 保持する情報

次を後から計算・確認できる情報を保持する。

- 記録上の作業時間。
- Focusの自然完了数。
- Quick Startの開始・完了・中止・終了選択・Focusへの継続。
- Quick StartからFocusへ継続した割合を計算するための関係と選択結果。
- Distraction申告数、Return数、未復帰・中止の結果。
- Distraction申告からReturnまでの時間。
- SessionごとのCurrent Task。

新しい分析用集計は、保存したSession・eventから計算できるようにする。詳細へ戻せない旧日別集計はそのまま保持する。

### 8.2 Snapshotとevent

- 現在状態はsnapshotに保持し、直接読み込んで復元する。
- 履歴・分析に必要な意味のある状態遷移をeventとして保持する。
- Event Sourcingにはせず、現在状態をevent replayだけから復元しない。
- snapshot、終了済みSession、対応するeventを一括で保存する。
- 保存の再試行でSession・完了・継続先・eventを重複作成しない。
- 保存ファイル全体にschema versionを持たせ、形式変更にはmigrationを用意する。
- 読込失敗・未対応バージョン・検証失敗時に初期状態で元ファイルを上書きしない。
- 保存失敗を表示し、保存できたものとして正常終了しない。
- 移行・復旧前には元データを保護する。

### 8.3 旧形式からの移行

旧形式の進行中タイマーは、新形式の進行中Sessionへ移行しない。

- 有効な設定・既存の日別集計・ラウンド進捗を引き継ぐ。
- 旧状態をバックアップとして保護する。
- 同じ種別の開始待ちへ移り、次の開始時に設定された全時間で新しいSessionを作る。
- 旧タイマーの経過時間・残り時間・締切・中断状態を、新しい進行中Sessionとして引き継がない。
- 旧期限が過ぎていても、それを根拠に新たな完了・作業実績を加算しない。
- 旧日別集計から、個別Session・開始日時・Interruption・eventを捏造しない。
- 旧日別集計の「完了した設定時間」と、新方式の「記録上の作業時間」を区別する。

この扱いは旧形式の移行に限る。新形式で保存した進行中Sessionは、7節に従って復元する。

## 9. UIとドメインの責務

- 当面は既存TUIを使用する。
- キー操作、テキスト入力、描画、ヘルプはTUIが担当する。
- 時刻取得、ファイルI/O、通知はプラットフォーム側が担当する。
- Sessionの状態遷移、計時の規則、ラウンド進捗、履歴に残す結果は`pomodoro-core`が担当する。
- コアにUI固有のロジックを持ち込まず、現在のRustコードベースに適した最小限のモデルとする。

## 10. 仕様上の確認例

| ケース | 期待する結果 |
| --- | --- |
| Quick Startを2分完了し、選択待ちの後に25分のFocusを完了 | 作業時間27分、Focus完了1回。選択待ちは加算しない |
| Focusを途中で中止 | 計時した作業時間は残り、Focus完了数は増えない |
| Distractionを申告してアプリ終了、再起動後にReturn | 同じ中断をReturnedで閉じる。Recovery Timeに終了中を含め、作業時間には含めない |
| 実行中のFocus・BreakでObservation Gapを検出 | 空白を加算せず停止し、手動再開を待つ |
| Quick Startの継続選択待ちで終了・再起動 | 選択待ちを復元し、継続先Focusを自動作成しない |
| 旧形式のFocusの期限が過ぎた状態で移行 | 旧進行中タイマーを移行せず、完了を加算しない。開始待ちから新しく始める |
